# Plan → Do → Verify

> Главное правило работы. Любая задача = три шага.

## 1. ПЛАН (перед тем как делать)

- Разобраться в задаче (читать код, контекст, план в `docs/plan.md`)
- Определить **критерии проверки**: как убедиться что сделано правильно?
- Крупная задача (новая фича, рефакторинг, архитектурное решение) → **уточняющие вопросы (5-20)** + план пользователю до начала работы

## 2. ВЫПОЛНЕНИЕ (делаем по плану)

- Следовать плану, не уходить в сторону
- При проблеме в процессе — вернуться к шагу 1, обновить план, согласовать
- Коммиты часто, push часто

## 3. ПРОВЕРКА (перед тем как сказать "готово")

- Проверить по критериям из шага 1
- **Перечислить конкретно что проверил**: `"Проверил: X ✓, Y ✓, Z ✓"`
- Без проверки задача **не считается готовой**

## Фейл проверки

Диагноз → скорректировать план → повторить. **Максимум 3 итерации**, потом обратиться к пользователю.

## Масштаб

| Размер задачи | Подход |
|---------------|--------|
| Крупная (новый чанк, рефакторинг, новая фича) | Полный PEV + план пользователю + 5-20 вопросов |
| Средняя (одна функция, ендпоинт, компонент) | План в голове, проверка обязательна |
| Мелкая (опечатка, переименование переменной) | Только проверка |

**Сомневаешься — выбирай более тщательный режим.**

## Конкретные проверки

| Что изменил | Что запустить |
|-------------|----------------|
| `.py` файл | `python3 -m py_compile путь/к/файлу.py` |
| `.yaml` файл | `python3 -c "import yaml; yaml.safe_load(open('файл'))"` |
| `.json` файл | `python3 -c "import json; json.load(open('файл'))"` |
| Backend (apps/api) | `cd apps/api && ruff check && mypy app && pytest` |
| Frontend (apps/web) | `cd apps/web && pnpm lint && pnpm typecheck && pnpm test` |
| SQL миграция | `alembic upgrade head` + `alembic downgrade -1 && alembic upgrade head` |
| AI-промпт | snapshot-тесты на стилевой контракт |
| Endpoint | `curl` или integration-тест с realистичным payload |
| UI компонент | визуальная проверка в dev-режиме + a11y-чек |

## Перед тем как сказать "готово"

ПЕРЕЧИСЛИ конкретно:

```
✗ "Всё ок"
✓ "Проверил: ruff ✓, mypy ✓, pytest 12 passed ✓, миграция применена ✓, нет PII в анонимизаторе ✓"
```

## Для важных задач — субагент `reviewer`

Запускать subagent `reviewer` или `code-reviewer` для независимой проверки с чистым контекстом. Особенно важно для:
- Анонимизатора (`apps/api/app/services/ai/anonymizer.py`)
- AI-промптов (style contract)
- Миграций БД (есть ли downgrade?)
- Юридических страниц (актуальность по 152-ФЗ)
- Auth-flow (нет ли утечек токенов)
