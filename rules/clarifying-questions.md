# Уточняющие вопросы

> Перед важными/крупными действиями — задавать **5-20 уточняющих вопросов**, прежде чем приступать. Не додумывать за пользователя.

## Когда задавать

Обязательно перед:
- Архитектурными решениями (выбор библиотеки, паттерна, схемы данных)
- Деплоем в production
- Удалением кода/данных/таблиц/веток
- Крупными рефакторингами (>5 файлов)
- Изменением публичных API
- Интеграцией с внешним сервисом
- Стартом нового чанка из плана

## Когда НЕ задавать

- Опечатки, мелкие правки
- Действия с однозначной интерпретацией
- Запросы на запуск тестов или линтеров
- Описанные в `docs/plan.md` детали (план уже одобрен)

## Формат вопросов

Использовать `AskUserQuestion` с правильно структурированными вариантами:

- **2-4 опции на вопрос** (не больше)
- Если рекомендую — первая опция с "(Рекомендую)"
- Краткий `description` объясняющий trade-off
- Если опции concrete code/UI — использовать `preview` с кодом/ASCII-mockup
- Связанные вопросы — в одном вызове AskUserQuestion (1-4 вопроса)

## Примеры

### Перед стартом UI-чанка

```
1. Какие референсы по стилю?
   → Свой Figma / Linear / Notion / Нет референсов
2. Тема?
   → Light / Dark / Toggle
3. Density?
   → Compact / Comfortable
4. Целевое устройство?
   → Desktop / Mobile-first / Равноправно
```

### Перед интеграцией с API

```
1. Где хранить API key?
   → .env / секрет-менеджер / параметр
2. Retry-стратегия?
   → Exponential backoff / fixed delay / без retry
3. Timeout?
   → 30s / 60s / 120s
```

## Принцип "никогда не выдумывать"

Если чего-то не знаешь — **сказать прямо**. Никогда не додумывать факты, числа, имена API, signature функций. Лучше задать лишний вопрос, чем сделать неправильно.

См. также [`never-make-up.md`](never-make-up.md).
