# Работа с планами

> Plan Mode — режим Claude Code, в котором запрещены любые write-операции кроме редактирования файла плана. Используется для согласования крупных задач до начала работы.

## Когда использовать Plan Mode

- Новый чанк из `docs/plan.md`
- Архитектурное изменение
- Рефакторинг >5 файлов
- Любая задача с неочевидным подходом

## Цикл работы с планом

1. **Plan Mode → Phase 1: Initial Understanding**
   - Запустить Explore subagent для изучения codebase
   - Прочитать связанные файлы плана и кода
2. **Plan Mode → Phase 2: Design**
   - Запустить Plan subagent для дизайна архитектуры
3. **Plan Mode → Phase 3: Review**
   - Уточнить детали через `AskUserQuestion`
4. **Plan Mode → Phase 4: Final Plan**
   - Записать в файл плана (`C:\Users\shepe\.claude\plans\...md` или `tmp/plans/`)
5. **Plan Mode → Phase 5: ExitPlanMode**
   - Представить план пользователю на одобрение

## После составления плана — ВСЕГДА говорить

> "План составлен. Перечитай его и убедись, что он идеален. Если хочешь что-то изменить — скажи, я поправлю. Не приступаю к коду, пока не одобришь."

## Изменения по ходу работы

- Если в процессе работы пользователь хочет что-то поменять — **сначала обнови план**, покажи изменения, получи одобрение, **только потом меняй код**.
- Не откатывать одобренный план без обсуждения.
- Не выходить за границы одобренного scope без обсуждения.

## Локальная копия плана

После составления или обновления плана:

```bash
mkdir -p tmp/plans && cp <путь_к_плану> tmp/plans/
```

Это даёт версионируемую локальную копию рядом с проектом (но в `.gitignore`).

## Шаблон плана

```markdown
# <Имя задачи> — план

## Context
Зачем эта задача, что прошло до этого, что нужно изменить.

## Recommended approach
Один рекомендованный подход (не все альтернативы).

## Files to change
- `path/to/file.py` — что именно изменить
- `path/to/other.tsx` — что именно изменить

## Existing utilities to reuse
- `apps/api/app/utils/foo.py:42` — функция `bar()` уже делает X
- `apps/web/lib/baz.ts` — хелпер `qux()` уже делает Y

## Verification
- `pytest tests/foo.py` должен пройти
- `curl http://localhost:8000/health` должен вернуть 200
- Lighthouse score > 90
```
