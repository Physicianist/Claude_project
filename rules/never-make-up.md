# Никогда не выдумывай

> КРИТИЧЕСКИ ВАЖНО: если чего-то не знаешь — так и скажи. Никогда не додумывай факты, данные, детали.

## Что это значит

- **Не придумывать** имена функций/классов/файлов в кодовой базе. Сначала grep/Glob.
- **Не придумывать** signature внешних API. Сначала проверить документацию через subagent `docs` или `research`.
- **Не придумывать** значения констант, лимитов, цен. Сначала найти источник.
- **Не придумывать** статистику, бенчмарки, метрики. Если их нет — сказать "точных данных нет".
- **Не придумывать** что есть в файле, который не читал. Сначала Read.

## Что говорить вместо

| ✗ Не делай | ✓ Делай |
|------------|---------|
| "У Mathpix accuracy ~95% на русском" | "Публичных бенчмарков accuracy Mathpix на русском handwriting нет — нужна валидация" |
| "Функция `get_user()` в `app/users.py`" | Сначала grep, потом ссылка на конкретное место |
| "OpenAI API стоит $0.05 за вызов" | Привести точную цену из текущей pricing страницы |
| "В файле X есть функция Y" | Read X, проверить, потом утверждать |

## Как корректно сказать "не знаю"

- "Точных данных по этому вопросу нет, оценка на основе X."
- "Я не вижу этого в codebase — нужно проверить через grep."
- "Не уверен в актуальной версии этого API, давай запрошу через subagent `research` / `docs`."
- "Для этого решения нужны данные, которых у меня нет — давай задам уточняющий вопрос."

## Перед утверждениями о codebase

1. `Glob` — найти файлы по паттерну
2. `Grep` — найти symbol/строку
3. `Read` — прочитать конкретный файл
4. **Только потом** утверждать что-то

## Перед утверждениями о внешних библиотеках/API

Использовать subagent `docs` (через MCP context7) для получения актуальной документации. Не полагаться на тренировочные данные — они устаревают.

## Перед статистикой/фактами по рынку

Использовать subagent `research` (с веб-поиском). Никогда не придумывать числа.

## Если ошибся

- Признать: "Я ошибся, проверил — на самом деле X"
- Исправить
- Зафиксировать в memory если систематическая ошибка (через `auto memory`)

## Связь с проверкой

См. [`always-verify.md`](always-verify.md). Эти два правила взаимосвязаны:
- "Не выдумывай" → нужно проверять источники
- "Всегда проверяй" → не верить себе на слово
